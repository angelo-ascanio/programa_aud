* The big idea here to solve the issue with the changes, is to took the certificate table only as a interconnected table to set all the data together.
* The idea here is to convert the current certificate into a versioning table, with the main certificate being there just to hold all the versions of that certificate.
* With this idea in mind we now have to fix the issue of solving older, inmediate and future audits.
* we can do any changes in our certificate, like literally anything, change sites, processes, shifts, dates, we don't care, but when we manually decide that is time to change the version for a new one, we then do two things, first we duplicate the current state of the certificate and create this new version but the children date related data stays in the older and not get duplicated. second we must solve any issue and with our audits. a popup appears with all the audits and we must select if they are gonna stay with their old certificate version (doesn't matter if is an older version) or gonna update into the new certificate version, and we classify the audits in:
  * Already done (Old): if an audit already finished all their steps completely. It gets set automatically to stay with their older version.
  * After execution (Finishing): After the execution of the audit is done (Real audit dates are set) but the audit still have steps left. Get not automatic selection.
  * Before execution (Incoming): This can be like 30 days before the last programmed date. Get not automatic selection.
  * Future audits: those are automatically set to move with the new certificate version.
* All those audits have the two options to click, stay with older or move with new version.
* When they stay with older, nothing happen to those audit records.
* When they move with the new version, all the related data towards that specific audit, move to the new certificate version, any time we call the id certificate, we stop using the older version and start using the new version.
* The overall reason is that because the clients can change anything at any time, and we must keep the older audits without those changes unless we manually decide that.
